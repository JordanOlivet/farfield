## Face directions (E.12)

Before: one indirect command per section and pass with all its quads; the
rasterizer culled back faces after the vertex shader had run on them.

Now each section's quads are stored in 12 groups (opaque by direction,
then translucent by direction; `Resident.groups`), and the draw loop emits
one command per run of adjacent groups whose direction can face the camera
(`FaceDirections.front`, core: +X faces only when the camera is past the
box's min X, with one block of slack). No shader change: `gl_VertexID`
starts at the command's `first`, as the translucent pass already relied on.
The stat line now says `N of M quads sent (face directions)`.

## Depth pre-pass (E.13, ADR-043)

The user asked to go after the per-pixel cost. Opaque faces now draw in
two passes: a depth-only pre-pass (`lod.frag` with `DEPTH_ONLY`: hand-off
and cutout discards only, color writes off), then the shaded pass with
`layout(early_fragment_tests)` (`EARLY_Z`), `GL_EQUAL`, no depth writes
and no discard. The translucent pass uses the `EARLY_Z` program with its
discards (it writes no depth). `GlProgram` takes `#define` lines;
`LodRenderer.Shader` holds each variant's uniform locations and `use()`
sets them. `invariant gl_Position` in `lod.vert`. The GPU time is split
per pass on the stat line (four timestamps per frame).
`/farfield debug prepass on|off` switches the pre-pass, not saved.

## Pre-pass cost (E.13, ADR-044)

The user asked to keep going on the pre-pass. A temporary command switched
pre-pass variants in one run (removed before the commit); second stat
line after each switch:

| Pre-pass variant | Pre-pass time |
|---|---|
| As in ADR-043 | 810 to 817 us |
| Vertex work only (`GL_RASTERIZER_DISCARD`) | 345 us |
| No discard at all (early tests) | 474 us |
| Hand-off discard only, no cutout test | 560 us |

Then, in a second run with a lighter pre-pass (texture read only for faces
with holes, hand-off lookup only near the game's grid, vertex outputs cut
under `DEPTH_ONLY`): 774 to 781 us, against 456 for the same build without
discard. The vertex cut changed nothing (345 us again). The discard itself
was the cost, so the pre-pass now splits sections in two lists (ADR-044):
`SOLID` (no discard) first, then the sections that overlap the game's grid
or have opaque faces with holes. `MaterialColors.CUTOUT` marks faces whose
baked texture has a texel under half coverage; `MaterialColors.cutout`
reads it per material from the mesher threads (true until built), and
sections meshed before the table was complete are meshed again.

Third run, same view:

| Pre-pass | GPU per frame | Pre-pass | Opaque | Translucent |
|---|---|---|---|---|
| Off | 3,630 us | off | 3,429 | 200 |
| On | 2,494 to 2,497 us | 520 to 521 | 1,765 to 1,768 | 208 |

- 171 of 793 sections in the discarding list (stat line).
- Captures on and off diffed: same 4 pixels of 4 million off by more than
  2 levels over the LOD part as in ADR-043's check. Night shot correct.
- The no-pre-pass reference read 3,421 us in the first run and 3,630 in
