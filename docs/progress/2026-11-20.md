# 2026-11-20 — A client API for the far terrain's depth (Create: Sky)

Branch `worktree-create-sky-compat` (worktree `.claude/worktrees/create-sky-compat`),
based on `feat/26x`: dev runs need Loom 1.19, which Rehearsal's jar is built with.

## Commits

- feat(api): the client API, the LOD depth for mods that draw over the far terrain (ADR-172)
- fix(api): the view distance is the geometry drawn, not the draw distance setting (ADR-173)

## What was done

- A player asked for compatibility with Create: Sky (3D clouds, cloud shadows,
  light shafts; NeoForge 1.21.1, All Rights Reserved). Studied from its own jar
  (concepts only here): it sizes its clouds from the vanilla render distance and
  reads Distant Horizons' depth, matrices and distance when that mod is present.
- Dev runs, NeoForge 1.21.1 at 3840x2019, render distance 8 unless noted:
  - Farfield + Create: Sky: no crash, no mixin conflict; clouds stop short of the
    LOD horizon, drawn over every LOD pixel (the main depth is cleared after the
    LODs), no cloud shadow on the LODs.
  - Create: Sky alone (Rehearsal's own dev client, so Farfield is not loaded) at 8
    and 32: at 8 a haze hides everything past 128 blocks, alike Farfield with
    `render off`; at 32 the cloud shadows show on the terrain. A vertical seam
    inside the clouds is the mod's own (seen without Farfield).
- ADR-172: `FarfieldClientApi` (`api`, API version 1): `requestLodDepth`, then
  `lodFrame()` with the LOD depth texture, the depth convention, the inverse
  view-projection (camera-relative) and the view distance. `LodDepthShare` copies
  the depth before it is cleared, only once a mod asked; `LodDepthMath` (`core`)
  builds the matrix as `lod.vert` does. Doc for other authors: `docs/api/client-api.md`.
- Check: a test-only bridge mod outside the repository (the scratchpad) plays
  the other author's part, feeding the API into the mod's distant-terrain path.

## Verified

- `LodDepthMathTest` (3 tests): the inverse finds camera-relative points back
  from the LOD depth up to 20 km, with an OpenGL projection and with a reversed
  infinite one (26.2's kind).
- `gradlew build`: all 8 jars (1.21.1, 1.21.11, 26.1.2, 26.2 on both loaders).
- Dev, NeoForge 1.21.1, Farfield + Create: Sky 0.1.0 + the test bridge:
  `LOD depth shared with skybridge (Create: Sky test)`, `LOD depth shared:
  3840x2019, depth format 0x81a6`, the bridge fed texture 66 and 4,104 blocks.
  The clouds reach the LOD horizon, distant LOD mountains stand in front of the
  clouds behind them, the cloud shadows fall on the LODs and across the vanilla
  edge. LOD renderer times unchanged (313 against 342 us render thread, 2,191
  against 2,224 us GPU, same view); the frame rate fell (251 to 209, 219 to 157
  fps) as Create: Sky now draws its far clouds.

- The user's Cobblemon pack (NeoForge 1.21.1, Sodium 0.8.13, Iris without a
  shader pack), Farfield + Create: Sky + the bridge: `LOD depth shared:
  3840x2019`, the LOD mountains hide the clouds behind them. Two findings:
  no clouds below a render distance of 4 (the game's own rule, which the
  other mod lifts only for Distant Horizons: the author's side, noted in the
  API doc), and the bridge got `33554440 blocks`, the pack's draw distance
  setting, not the geometry drawn. ADR-173 fixes the latter; all 8 jars
  build. Checked in the same pack: the shared distance starts at 95 blocks
  and grows with the load, 4,634 blocks 6 s in, 31,977,114 at 18 s: with the
  preview on and the setting at its maximum, the preview's coarsest tiles
  really reach that far, so the announced distance stays that large there.

## Not verified

- 26.x and Fabric in a game (no consumer there), draw distances past 4,096
  blocks with the other mod's far clouds, the cost of the copy alone (not timed).
