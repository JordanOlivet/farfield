### Done

- Rehearsal built with 1.20.1 (Fabric and Forge jars in its `output/`).

  Forge-only config hooks the head of `NoVizFallback.windowHandoff`, whose
  returned supplier creates the window right after the hints.
- Farfield on Forge 47 ran on an OpenGL 3.2 context (`LOD rendering on an
  OpenGL 3.2.0 NVIDIA 621.01 context, its 4.x functions from the driver's
  extensions`): neither injection of `WindowMixin` finds its call there.
  Same hook as Rehearsal's in the forge project (`farfield.forge.mixins.json`,
  `NoVizFallbackMixin`), calling the probe now shared in `GlContextProbe`.

### Verified

  colors, the four settings tabs. After the probe moved: `OpenGL 4.6
  context available` again, 421 drawn.

- `build` with every version and 1.20.1: green, 12 jars; the Forge jar's
  manifest lists the four mixin configs. A first run failed on 26.3
  (`GlContextProbe` imports GLFW): left out there as `WindowMixin` is.

## 1.20.1 port: client mode and streaming (plan D.4)

### Commits

- `fix(1.20.1)`: no stream session or client pipeline starts while the game
  stops; the Forge dev server in a run dir of its own.

### Done

- The Forge dev server runs in `forge/runs/1.20.1/server` (it shared the
  client's run dir, so a client joining it overwrote its `latest.log`).
- Forge 47 fires its shutdown event before the last client tick: after
  `StreamClient.onClientStopping` closed the mirror, that tick opened a
  second session (`LOD streaming to Dev: ... (session 2, same store)` on
  the server, `coarse levels are fetched again` on the client) and a mirror
  nothing closed. `StreamClient` and `LodClient` keep a `stopping` flag:
  nothing opens after it.

### Verified

- Client mode against the vanilla 1.20.1 server (`runVanillaServer
  -Pmc=1.20.1`, a fresh client store): Fabric `Client mode: building the
  LODs`, store closed with 536 chunks ingested; Forge the same lines, 453
  chunks ingested. A short run on a new world: 17 sections drawn, only what
  the server sent.
- Streaming, Fabric server and client: `LOD streaming from the server
  (session 1 ...)`, 5,717 KB in the first 10 s (1,952 sections, 89 preview
  tiles), 423 sections drawn, the view the same as single player's, mirror
  closed with 1,273 sections. Again after the fix: 807 sections held at the
  join (`same store`), closed with 1,255.
- Streaming, Forge server and client: 5,668 KB in the first 10 s (1,837
  sections, 89 preview tiles), 423 sections drawn. After the fix: one
  session, the mirror closed once (992 sections), no session 2.
- `build` with every version and 1.20.1: green, 12 jars.

### Not verified, and one open point

- A Forge 47 dev client joining the vanilla server stalls at login about
  two times in three: the server logs `Dev joined the game`, the client
  stays on the connect screen and gives up after 30 s (`Failed to connect
  to the server`); a thread dump shows nothing blocked. Not Farfield's: a
  Forge client with Rehearsal alone (its own dev run) stalled on 4 joins of
  6, and Farfield without Rehearsal stalled too. With Farfield: 9 stalls of
  15 joins; none of 3 more joins with a temporary mixin on `Connection`
  stalled, so timing plays. Never seen against the Forge dev server (2
  joins) or with a Fabric client (1 join of the vanilla server, 2 of the
  Fabric server). Whether a launcher install does it is not known.
- A Fabric client on the Forge server and the reverse; two clients at once.
- Rehearsal's `close-game.ps1` finds no Forge 47 JVM to close (`no game JVM
  of <run dir> to close`): the dev run's command line does not name the run
  dir. A stalled run was closed by its window title instead.
