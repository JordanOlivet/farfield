## Fix: the mirror emptied again and again on the server

The user, walking on the NeoForge server: the world "disparait et
réapparait" as chunks generate. The client log: 31 times "key tables
differ from the server's, emptying the mirror", several a second. Cause:
the preview layer adds its two mask keys to the mirror's block-state
table; the next key the server sent (new chunks, new blocks or biomes)
then had another id here, the mirror emptied, the preview added its
masks again. Fix (protocol 3): every store reserves the masks and the
water of kelp when it opens (`LodLevel.open`), so they reach the mirror
with the server's ids; the welcome tells the server's table sizes and
the mirror is drawn only once it holds them; the client announces the
keys it received from the server (kept with the epoch, a mirror whose
tables differ starts again) instead of its tables' size, which would
have made the server skip keys silently; after two disagreements in a
connection the client builds its own LODs instead of looping.
Fabric dev server and client, preview on, then a teleport 6,000 blocks
away into new terrain: one session from start to end, no disagreement,
2,025 sections and 256 tiles after the teleport, view settled at 15.5 s.
