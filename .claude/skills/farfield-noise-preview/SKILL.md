# Farfield noise preview

The preview draws terrain not generated yet as LOD tiles, built from the noise router in the integrated server. Change it at tile level, never per column.

- Pregeneration (ADR-123, `PreviewPregen`, `PregenTasks`): tasks of tiles within a radius, nearest first, at the finest grid, in the pool slots the players' tiles leave free; saved in `<world>/farfield-pregen.txt`; the spawn's made by a dedicated server at start (`preview_spawn_radius`); held while players are online unless `pregen_when_players=run`. A dimension with a running task and no player is scheduled too. Read the `Noise preview pregen <id>:` lines (start, a minute's progress, done). While an LOD import runs or waits (ADR-124), tasks build only within 1,024 blocks of their center (`PreviewPregen.NEAR_WHILE_IMPORTING`), so a player who joins early sees the spawn area; the import's end lifts the limit. Built 2026-11-09 and not yet seen in a run: check both log lines on a dev server before claiming it works. Test on a dev server with a small `preview_spawn_radius` and a `pregen start` far away (the test world's spawn tiles are often built already: `done ... (all built already)`).
- Player's choice of features (ADR-121, D.3): `PreviewVoxels.Shown` (trees, plants, others) filters at mesh time on the client, tree blocks by tag (`TreeMaterials`), snow and ice following the run they touch below. A new kind of stored preview content must say which of the three it belongs to, or it ignores the settings. Prove a switch ran from `LOD preview features now ...: N preview sections meshed again`.
- Mod terrain and worldgen: handle a class of feature, never a mod by mod list. The user rejected per-feature handling: "Car si on gère chaque feature une par une on y arrivera jamais". Built (ADR-079, `PreviewFeatures`, tile format 11, protocol 6): the world's own features are grown on the stand-in terrain, so every mod's trees, plants and rocks follow the game's placement, away from villages. `PreviewTrees` is gone. Not yet verified in a dev client. Built as plan item D.3 (2026-11-09), not yet seen in a client run: the toggle per kind is no longer open.

- Feature toggles (D.3): trees, plants, and the other features with villages are bits of `RenderConfig.previewFeatures` (`FEATURE_TREES`, `FEATURE_PLANTS`, `FEATURE_OTHERS`), read through `RenderSettings.previewShows`. `PreviewVoxels.build(..., PreviewVoxels.Shown)` leaves a hidden kind out of its blocks and its light sources (`lightShown`). `TreeMaterials` tells a tree block by its vanilla tags (logs, leaves, wart blocks, huge mushrooms, mangrove roots, bee nests), so mods' trees count. `LodRenderer` meshes the preview again when a bit changes, as it does for `preview_light`. Chat: `/farfield preview trees|plants|others on|off`; the option rows reuse the `farfield.options.preview_feature.shown|hidden` captions, so both lang files change together. Verify: one capture per kind off, at a forest, in the Fabric pack.

- Who builds: the integrated server in single player, and a dedicated server only when `preview=true` in `farfield-server.properties` (default true, ADR-068), which then streams the tiles to its players (`farfield-lod-streaming`). `LodServer` gates this on `StreamServer.streamsPreview()`. `/farfield preview on|off` and the `noise_preview` setting toggle the client side. The setting's tooltips (`farfield.options.noise_preview.tooltip` and `preview_threads.tooltip`, in `en_us.json` and `fr_fr.json`) state who gets the preview: they said "Single player only" until 0.2.0, when servers started streaming it. When the server or client scope of the preview changes, edit both lang files in the same commit. Not yet verified on a dedicated server: check a run's preview log lines before claiming it works. Log lines: `Noise preview of <dim>: building ...` then `every tile within 4096 blocks is built`.
- Tiles are 512 x 512 blocks, 129 x 129 height samples every 4 blocks, bilinear per block, shared at tile edges so neighbors agree on the border. Keep the shared edge samples when changing the step.
- Pyramid (ADR-126, tile format 19, protocol 10; levels 3 to 5 from ADR-135, format 22, protocol 11): tiles of levels 0 to 5 (`PreviewPyramid`), a level-L tile `512 << L` blocks with the same 129 x 129 samples; level 2 over 4,096 blocks, level 1 within 2,048, level 0 within `preview_features_distance` (1,250), coarsest first. Store folders `preview/L<level>/`; readers see level-0 views only (`PreviewStore.read/summary(x, z)`: the finest tile over the place, cut by `PreviewTile.expand`, the canopy grown into feature runs); view listeners hear level-0 places, tile listeners (`addTileListener`, the streaming) raw keys `PreviewStore.key(level, x, z)`. Levels 1 and 2 take canopy, plants and ground from `PreviewProfiles` (per biome, measured on level-0 tiles, a new biome sampled on 4 x 4 chunks; minute line `N biomes sampled, M known`). Since ADR-135 (tile format 22, protocol 11) the pyramid has levels 0 to 5 (`PreviewPyramid.LEVELS`), and from `GROUND_ONLY` (level 3) a tile holds the ground only: the surface rules per cell at its center (`CoarseGround` over `SurfaceColumns`), the snow decided at the center by the cell's own biome; no plants, canopy or biome sample (levels 1 and 2 keep the profiles). Time a coarse tile and compare its tops with the level-0 tile stored there: `farfield spike coarse <level> at X Z` (run `spike tile at X Z` first; log lines `Coarse spike:`). To see when each level was whole after a `pregen start`, read the last write time of the files in each `preview/L<level>/` of the server's world (`neoforge/run/world/...` on the dev server, not `saves/`). Since ADR-136 (E.3b) the range is each player's draw distance: the fog distance (256 to 32,768, default 4,096, off = 4,096), in single player as is, on a server by the client's hint at most `streaming_radius` (log `left within N blocks` names it). The client's preview layer draws levels 0 to 7: a far section (draw level 5 and up) reads the stored coarse tile of level `drawLevel - 2` or coarser through `PreviewStore.coarseSource`, built by `PreviewVoxels.buildFar` (ground, sea, ice only), never level-0 views (64 views and masks a section would cost hundreds of MB); tiles without real data share `EMPTY_MASK`. Prove far levels are drawn with `/farfield debug levels` (purple 32, pink 64, white 128) and compare a capture with `/farfield fog 4096`. To test the server's clamp on one PC: a Fabric dev server (its own run dir) with `streaming_radius` lowered, and a NeoForge client joining it (`runClient -PquickPlayServer=localhost:25565 -PclientUsername=Dev`; the server needs `op Dev` on its stdin, the run dirs' configs restored after). Since ADR-137 and ADR-138 (E.3c, E.3d): real and preview levels 0 to 15 (`LodKey` 5 bits of level, preview keys +16), tile levels 0 to 15, distance up to 2^25, quarters outside the world border skipped. At such levels watch three traps, all hit once at the border: any walk over a tile's `(1 << level)^2` level-0 places (a billion at 15: `PreviewStore.placesUnder` walks only places read above level 5), any int product of spans (`span * span` is 2^34 at level 15: use longs), any per-section array sized by `2 << level` (the renderer's chunk columns: none above level 7). A float frustum with far 67 M and near 1 culls everything: keep near >= far / 4e6. Performance at those distances is not settled: on the Fabric pack (2026-11-13) the view reached the border and showed right, but the frame rate was low and it stuttered while moving. Measure before claiming it is done: the `LOD renderer` stat line (render-thread and GPU microseconds, sections drawn) and the meshing line, standing and moving, at 4,096 and at the maximum. Test at the border from a dev client with `fog_distance=33554432`, a `tp` to the spawn then to 29,000,000 (the teleport is what found the overflow), and `JAVA_TOOL_OPTIONS=-XX:-OmitStackTraceInFastThrow` when an exception shows no stack. A level-0 tile is built one quarter at a time (ADR-127): each quarter's build writes the tile, the next quarter keeps the samples already built, and the tile's `quarters()` mask says which are built. `PreviewStore` caches a level-0 view only when all four quarters are built, so a half-built tile is never served from the cache. A quarter's feature columns merge into what an earlier quarter spilled into them (`mergeFeatureColumn`), they are not overwritten. The front-first order is a temporary `-Dfarfield.previewFront` switch; its client A/B (2026-11-10) is not read yet. A pregen task marked done before a format change stays done: `farfield pregen start` builds again. The far grid (`fillBetweenSamples`, `NoisePreview.grid`) is gone.
- Coarsest level first (ADR-139, `PreviewPyramid.twoFronts`, `FAR_FRONT_FROM` = 15): every other turn goes to the coarsest level's quarters by distance, so the first image reaches the border. Measured in a NeoForge dev client from an empty preview (970 quarters): the coarsest level whole at 11.3 s against 71.7 s with the rings alone; the detail within 1,024 blocks at 32.3 s against 30.7 s. A front of every ground-only level (3 to 15) reached the border at 11.7 s but held the detail back to 56.2 s: do not widen it. Procedure: delete the world's `farfield/preview` folder before each run, read the fill line `coarsest level whole at`, and keep any A/B switch marked `TEMP` out of the commit (`grep -rn TEMP` first).
- Quarters in rings (ADR-127, tile format 20): a tile is built a quarter at a time (`PreviewTile.quarters()`, 64 samples a side), ordered by distance with a 1,024-block lag per finer level (`PreviewPyramid.order`; a pure circle, the front priority measured no faster); views show each quarter from the finest tile with it built; a level-0 quarter computes a chunk around it and merges what neighbors spilled (`mergeFeatureColumn`). Biome samples are queued apart; a coarse quarter waiting for one is incomplete and built again. While the coarse disc grows, level 0 holds at most half the threads in flight (ADR-128): one queue let slow level-0 quarters stall the disc. The minute line counts quarters; the fill line gives `coarse disc whole at`.
- Features (ADR-079, replaces the ADR-040 `PreviewTrees` lists): `PreviewFeatures` runs each chunk's placed features on the tile's ground in a stand-in world, unless the server settings turn them off. Check the minute line `Noise preview of <dim>: ... N features failed` first when trees, plants or rocks look missing. Feature columns are stored per 2-block voxel column; each run is a `PreviewTile.featureRun(y, length)` word, followed in the column's int array by its material id. Y and length count 2-block voxels: `featureRun(40, 4)` put coral at block y 80, so block y 40 to 43 is `featureRun(20, 2)`. Tree kinds are baked into the tiles: after changing a tree rule, clear `<save>/farfield/preview` in the dev world, or bump the tile format, to see it.
- Ground (ADR-101, tile format 14): the top and filler block per cell come from the generator's own surface rules (`NoiseBasedChunkGenerator.buildSurface`, the overload without a world region), run on the one column each 4-block cell keeps, by the generator's own rule objects (ADR-134, `SurfaceColumns`: one rule context and one rule tree per tile, the rule's `tryApply` and the eroded badlands' pillars found by the shape of their parameters), not from a biome guess. Before ADR-134 they ran `buildSurface` on a stand-in chunk per chunk (`PreviewFeatures.ruled`); that path is now the fallback. Pitfalls: `ChunkAccess.getHeight` already returns the top block (a first run read the block under it everywhere); the noise chunk is built once per tile with an empty `Beardifier`, since the real one asks the real world for structure references and generates chunks from a preview thread; a throw in the rules, or a missing piece of the column path, falls back to the stand-in chunks (logged once); the guess is the last resort. Judge the ground with `/farfield spike surface <biome>` (see `farfield-feature-spike`) before judging it by eye. The rules' stand-in (`PreviewFeatures.rulesChunk`, ADR-125) stands at the noise status, not carvers: a block set there updates the world-generation heightmaps the rules read. At carvers, with the heightmaps primed once, 65 tiles came out wrong (swamp water, powder snow, badlands read under the blocks the rules set). Every format bump rebuilds all preview tiles on a server: warn the user of minutes of background work after a deploy.
- Climate and biome samples are the pack's cost (ADR-102): in the pack one climate sample costs about 0.5 ms under C2ME and Terralith's splines, so a per-block or per-quart-in-3D biome read made a tile take 35 to 55 s where dev took 5. The surface rules and the stand-in read one biome sample per quart column per tile, shared with the features. Never add a per-block or 3D biome lookup to a preview path without timing it in the pack. Check the surface rules' noise chunk computes no density (`SurfaceNoise`): its preliminary surface level is the bottom of the world, so no mod density runs from a preview thread for it.
- Storage: zstd files `preview/t.<x>.<z>.ffp` in the world save (`PreviewStore`). Before a tile is written, `PreviewStore` runs its key-table hook (`beforeWrite`, as `SectionStore` does): a tile names block and biome ids that must already be on disk, or a restart reassigns them and the tile shows the wrong blocks (ADR-080). Any new store that writes key ids takes the same hook. When the format changes, delete the old folder at open (the ADR-038 `L8` folder was removed that way). Never read old-format tiles.
- Cost, from the saved game logs: about 0.2 to 1.1 s per tile on 4 threads (`Noise preview threads: 4`, 2026-10-24 logs: the 4096-block radius in about 2 min), about 2.6 s per tile on the 2026-10-18 logs (about 5 min). Tiles are chosen nearest first, then in front of the view (`NoisePreview.schedule`), on the `preview_threads` pool; the planner wakes every 0.5 s so idle threads get work quickly. Before proposing a new stat or log line, grep the code and the saved logs: `Noise preview of ...: N tiles built in the last minute` already prints every minute. Thread count: `preview_threads` (Auto by default). Judge a change from the log timings, then relaunch: the second open must build nothing and still print `every tile ... is built`.
- Block light (ADR-117, tile format 17): every block a feature places with a light emission is kept in the tile's own light list (`PreviewTile.setLights`, position and emission), whatever it becomes in the runs: sea pickles are stored as water and a single source never fills a 2-block feature voxel, so the runs alone held no light source (probe of the 35 test-world tiles, 2026-11-07). `PreviewVoxels.blockLight` lights each voxel with the brightest `emission - distance`, walls not counted, sources over real chunks left out; the client setting `preview_light` (`/farfield preview light on|off`) turns it off and meshes the resident preview again. The minute line counts `light sources`. Prove a toggle ran from the render log: `LOD preview light switched off|on: N preview sections meshed again` (seen: 630 and 673 sections on the Fabric pack, 2026-11-07); a command reply alone is not proof. Check at night over a warm ocean (208, 110, 2700 on `farfield-test`, `gamerule doDaylightCycle false`, `time set midnight`).
- Dug lakes (ADR-118, tile format 18): the features' blocks under the tile's surface were all dropped, so surface lava lakes (lava 1 to 6 blocks under it) never showed. Now `PreviewFeatures` follows the air and liquid written in the top 8 blocks of land columns (`dug`, resolved in `storePits`: open from the surface down, fluid filling from the bottom) into `PreviewTile.setPits`; `PreviewVoxels.dig` lowers and fills them on level 0 and puts the fluid on the coarse top voxel where it covers half the footprint. The minute line counts `dug columns`. To find what the features place under the surface, a temporary log in `collect` before the `y < ground` drop, with the depth `ground(x, z) - y`, then cluster the positions by 64-block cells: that found the lakes (2026-11-07). Check spot: -925, 120, 1390 facing 0, 19 on `farfield-test`.
- Per-column tile reads in `PreviewVoxels` (2026-11-08): the client's `Tiles` is `PreviewStore.read`, a shared lock and an LRU lookup per call. A read per column (ADR-118's `dig` used the raw source) made preview mesh jobs 3 to 10 times slower (15.6 against 4.1 ms per job, pack A/B). Read per-column data through `NearTiles` (each tile of the section's area once) or `TileCache`, never `tiles` directly; `PreviewTest.aSectionLooksUpItsTilesAFewTimesNotOncePerColumn` counts the source reads. After a preview change, compare the `LOD meshing: N jobs ..., X us per job` lines of the pack client at the same spot and script before and after (job-weighted mean), not only the tile minute line.
- Real chunks (ADR-039): a preview column beside a loaded real chunk goes down to that chunk's real ground (`PreviewVoxels`), so a preview shore beside real sea drops to the sea floor. Real columns carry two mask materials: opaque up to the real ground, translucent (`farfield:preview_mask_fluid`) up to the real fluid's top. Preview water thus shows no wall toward real water, while preview land shows its cliff. Real ground and fluid top are read per chunk from the real level-4 voxels (`PreviewLayer`). Exception (ADR-109): a real chunk touching a preview chunk takes its lowest solid ground over the chunk, read at the finest stored level (`RealGround.lowest`), because the level-4 value sits near the chunk's highest columns and left a real pit open beside the preview. See `farfield-lod-renderer` for the renderer side.
- Verify in the Fabric dev client at a spot never generated (for example 6000, 0): from above, then low at y 120 toward real terrain. Procedure in `farfield-dev-client-check`. NeoForge and Sodium are not verified yet.
- Snow on tree tops (ADR-049): a kind carries a snow layer when its crown top is cold enough. Spruces are `TIERED`, pines narrow cones, both without row corners, as vanilla's placers. Detect vanilla placers with `instanceof`, never by class name (intermediary on Fabric outside dev). To compare a preview tree with a real one, find real terrain beside the preview and toggle `/farfield preview off`: what vanishes is preview. When a shape looks wrong, dump the stored tile's kinds from a temporary core test (`PreviewStore` on `<save>/farfield/preview`) before changing code.
- Icebergs (ADR-054): frozen ocean spires come from vanilla's surface rule (`SurfaceSystem.frozenOceanExtension`, three noises from the world's `RandomState`), not from features: the preview raises sea samples to the same top. Read vanilla's surface rules before inventing a shape for any other terrain the preview lacks.
- Spikes on the pack server: one at a time through its console (`rcon-cli`, the deploy skill has the host); a negative coordinate is read as an option by `rcon-cli`, so use positive places. Count `Heights spike: done` or `Feature spike: tile` in the server log to know a run ended. Parallel spikes skew each other's times: only the precisions carry over.
- Timing far tiles on a dev server (2026-11-10): write a scratchpad `.sh` that feeds the spike commands on stdin, then run it with `bash file.sh` in the background: `sleep 100`, `echo "farfield spike tile at 20000 20000"`, `sleep 25`, another spike line, `sleep 30`, `echo stop`, piped into `./gradlew.bat :neoforge:runServer --no-daemon --console plain > log 2>&1`. The server prints `Done` about 2 s after launch, so the first command waits until then. `farfield spike tile at X Z` builds one tile at that position (`tileSpikeAt`); `farfield spike tile BIOME` builds one over a biome (`tileSpike`). Read the answer with `grep -E "spike|Spike|Done \(|exit "` on the log, not by polling the task output.
- Comparing two tile sets: first rebuild the same code twice, from nothing (delete the dev world's `farfield/preview` folder, then `farfield pregen spawn 4096` and the far tile commands), and diff the two. Two builds of one commit differed on 41 of 234 tiles (a few feature columns, a thread race, not looked at, 2026-11-10). Only the difference beyond that floor belongs to the change. The temporary probe reads two folders from the env vars `PROBE_A` and `PROBE_B` and prints per tile which heights, tops, fillers, biomes and feature columns differ.
- Inspecting a stored tile or a block's class: write a temporary test under `core/src/test/java/io/lakio/farfield/core/probe/` that prints `PROBE` lines, run `./gradlew.bat :core:test --tests '*TileProbeTest' --no-daemon -i --rerun-tasks` (without `--rerun-tasks` Gradle reuses the cached result and prints nothing), grep `PROBE`, then delete the folder before committing.
- Plants and villages (ADR-041): `PreviewTrees` also follows huge mushrooms, bamboo, block columns (cactus), single blocks and random patches. Blocks without a collision shape that the LODs draw as plants (grass, flowers, ferns; ADR-059, ADR-060) are kept: each chunk stores its plant kinds and their count per chunk (`PreviewTile.setPlants`, `plantEntry`), read from the biome's vegetal features. Level 0 places a plant in the block above the ground where the block's hash falls under the chunk's cover; coarse levels use the covered ground (see `farfield-lod-renderer`). Plant patches try with `PLANT_PATCH_SUCCESS` (0.2, tile format 10): measured, not guessed. To check a density, count the plants on the ground of generated chunks (the block above the `MOTION_BLOCKING_NO_LEAVES` top, so plants under a forest canopy count; `ChunkAccess.getHeight` already returns the top block, `Level.getHeight` the block above it) and compare the share of columns with `1 - exp(-n / 256)` of the preview's `grows ... N plants` line. Find a test biome at its surface: `getBaseHeight(..., OCEAN_FLOOR_WG)` above sea level, then the noise biome at that height, with the same biome 64 blocks around; `findClosestBiome3d` at a fixed y returned a savanna under a mangrove swamp and a plains over the sea. 0.8 drew about four times the real plants in plains, meadows, savannas and forests. Plants are built only in full sections, not in the single layers built for neighbor faces (`layerAxis >= 0`), where a plant would hide a neighbor's face. Each kind needs its ground (grass or snow, mycelium, sand).
- Villages: `PreviewVillages` takes the village structure sets, asks each placement for its candidate chunk per region, and keeps it when a village of the set accepts the biome. Houses are approximate boxes, not the game's pieces. Placement on land: try the candidate center first, then retry around it many times. A center in a lake left 2 houses on an islet until the tries were raised to spread along the shore. Judge a village by its houses, not by its center.
- Density reads are cached per column (ADR-057): the surface search reads `finalDensity` through a `SinglePointContext`, which ignores vanilla's cache markers, so each read recomputed the 2D terrain functions (continentalness, erosion, ridges, their shift noises, the splines). `ColumnDensity` honors `flat_cache` and `cache_2d` (last column) and `cache_once` (last point), as `NoiseChunk` does. Any new density read in the preview must go through `ColumnDensity`. Measured on a frozen sea: a tile 569 to 259 ms, the 558 tile files byte-identical. The minute line prints the stage times (`heights`, `cells`, `biomes`, `villages`, `trees`, `write`). Left after the caches: biome lookups (31 % of samples, mostly the frozen-sea check per cell) and the 3D noise (25 %).
- Coverage across a pack: the server logs hold one `Noise preview: <biome> grows N trees per chunk of K kinds, M plants of J kinds` line per biome. Survey them on the pack server (`data/logs`, rotated `*.log.gz` plus `latest.log`) with `zgrep -h "Noise preview: .* grows"`, then count per namespace the biomes under 1 tree per chunk. Last survey (2026-10-28, 190 biomes): 52 of 60 Biomes O' Plenty biomes and 34 of 53 vanilla biomes were under 1 tree per chunk, so the gap is mod trees the preview does not recognise.
- Measure before choosing an option (2026-11-10, `FeatureCosts`, built but not yet read in a run): `farfield spike tile at X Z` also logs `feature kinds of N ms:` with each kind (plants only, trees, others, others with plants, nothing set) as time and share of the feature time, then the costliest features. A feature's time leaves out the stand-in chunks it asked for. The user asked for the measure and then the option: take the split first, then pick the option the numbers favour, and say which share it targets.
- Biome profiles persist (ADR-130, `PreviewProfiles.save` and `load`): saved at server stop in `<world>/farfield/preview/profiles.bin` when they changed, dropped on load when their stamp (features left out, biomes of the generator) differs. Check: delete the file, run a dev server with one spike tile and a stop, confirm the file exists, then start again on the same world: the second start must sample no new biome. Not yet verified; the check script is in the scratchpad of that session, not in the repo.
- Stopping the preview (`NoisePreview.stop`, server stop): never `shutdownNow()` first. Its threads read mod jars (Cobblemon's structure templates, fossils), and an interrupt inside such a read closes that jar's channel for the rest of the session (`ClosedByInterruptException` on every later stop). Stop by clearing the queue, `shutdown()`, waiting 10 s, and calling `shutdownNow()` only as the last resort. Check the `stopped` flag before the features stage and before `world.preview().write`, so a stopped tile writes nothing after the stores close.
- Heights defect, found 2026-11-10 and not fixed (study `docs/analysis/preview-coarse-to-fine.md`): the neighbor search (`NoisePreview.surface`) checks only 16 blocks above its result, so a sample that falls into an open cave or under an overhang pulls the next ones under it. 1 to 2.7 % of the samples differ from the search from the top, mostly too low, by tens of blocks. `farfield spike heights at X Z` compares both searches with the generator's exact height (`getBaseHeight`) on the differing samples: judge any change to the search against that, not by eye.
- Known and not caused by the preview: a darker vanilla water rectangle at the render distance also shows with the preview off. Log it as a separate defect.
- Preview drawn over real water or sand (double water blend, preview grass on real sand): the mask is missing the real top-level sections near the player. Fix the streaming side first (`farfield-lod-streaming`, background fetch of the real terrain). Water above the sea reads sky light 15: that is not a lighting bug. The exception is a preview face on a tile border: it took the mesher's full-sky fallback where the neighbor tile's light belongs, which is the suspected cause of white bands on the preview's sea floor. Cause found (2026-10-25), replacing the earlier tile-border candidate: a ground voxel under the sea that is filled only partly shows a neighbor's side above its fill, and `PreviewVoxels` gave that face full sky light 15 instead of the water's. The fix lights those voxels with the water's light (the `water >= 0 && blocks < s` branch of the sky-light write in `PreviewVoxels`). Regression test: `PreviewTest.partlyFilledGroundUnderTheSeaTakesTheWatersLight`; it fails without the fix (`expected: <7> but was: <15>`). Unit proof only: confirm with an A/B capture at the same spot, fix on and off, before calling the bands gone. A preview regression test proves its fix only if it fails without it: `git stash push` the one main file, run `./gradlew.bat :core:test --tests "*PreviewTest"`, expect the failure, then `git stash pop`. Procedure in `farfield-dev-client-check`.
- Sea floor under preview water: on `farfield-test`, `/locate biome minecraft:warm_ocean` gave 208, 75, 2784. Teleport to y 95 with pitch 22 to look at the preview sea from above the water. Add that spot as a row in `docs/test-worlds.md`.
- Underwater features (corals, sea-floor trees) were missing from the preview (user pass, 2026-10-27): the tiles held them, but `PreviewVoxels`' `Stamp` wrote feature voxels only into air, and a preview column fills its sea before the features are stamped. Fixed by ADR-108: a feature voxel also takes the place of the preview's water (`Stamp.water`, set from `tile.water()` in `features`). When a feature shows in the real LODs and not in the preview, confirm the tile holds it first, then read the stamp. Kelp and seagrass in the preview's water: ADR-105.
- Java pitfall in feature code (ADR-079): fastutil's `IntArrayList.add` returns `boolean`, so chained calls do not compile. Write `list.add(a); list.add(b);`. The compile error seen: `PreviewFeatures.java:326: error: boolean cannot be dereferenced .add((int) key).add(best);`. Compile the loaders (`:neoforge:compileJava :fabric:compileJava`) after each such edit.
- Preview load starves chunk generation (measured 2026-10-28 on the 16-core pack server, `Noise preview threads: 5`): one minute of the preview used 255 s of CPU (about 4.3 cores) against 35 s for the chunk worker, and a tile took about 6.8 s with features. Real terrain then arrived only as fast as worldgen got cores. Linux ignores Java thread priorities, so a lower priority did not yield. Read the load with the `LOD CPU usage over 60 s` line and the minute line `Noise preview of <dim>: N tiles built in the last minute`.
