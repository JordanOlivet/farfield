# Farfield noise preview

The preview draws terrain not generated yet as LOD tiles, built from the noise router in the integrated server. Change it at tile level, never per column.

- Mod terrain and worldgen: handle a class of feature, never a mod by mod list. The user rejected per-feature handling: "Car si on gère chaque feature une par une on y arrivera jamais". Built (ADR-079, `PreviewFeatures`, tile format 11, protocol 6): the world's own features are grown on the stand-in terrain, so every mod's trees, plants and rocks follow the game's placement, away from villages. `PreviewTrees` is gone. Not yet verified in a dev client. Still to do: a toggle per category (trees, plants, rocks) to switch off what bothers the user.

- Who builds: the integrated server in single player, and a dedicated server only when `preview=true` in `farfield-server.properties` (default true, ADR-068), which then streams the tiles to its players (`farfield-lod-streaming`). `LodServer` gates this on `StreamServer.streamsPreview()`. `/farfield preview on|off` and the `noise_preview` setting toggle the client side. Not yet verified on a dedicated server: check a run's preview log lines before claiming it works. Log lines: `Noise preview of <dim>: building ...` then `every tile within 4096 blocks is built`.
- Tiles are 512 x 512 blocks, 129 x 129 height samples every 4 blocks, bilinear per block, shared at tile edges so neighbors agree on the border. Keep the shared edge samples when changing the step.
- Far tiles compute heights every 8 blocks (beyond 1,024 blocks) or 16 (beyond 2,048) and fill the rest bilinearly (`fillBetweenSamples`); the grid is stored (format 5) and a tile is rebuilt finer when a player comes closer (`NoisePreview.grid`). Readers never see the grid: keep it that way.
- Features (ADR-079, replaces the ADR-040 `PreviewTrees` lists): `PreviewFeatures` runs each chunk's placed features on the tile's ground in a stand-in world, unless the server settings turn them off. Check the minute line `Noise preview of <dim>: ... N features failed` first when trees, plants or rocks look missing. Feature columns are stored per 2-block voxel column; each run is a `PreviewTile.featureRun(y, length)` word, followed in the column's int array by its material id. Y and length count 2-block voxels: `featureRun(40, 4)` put coral at block y 80, so block y 40 to 43 is `featureRun(20, 2)`. Tree kinds are baked into the tiles: after changing a tree rule, clear `<save>/farfield/preview` in the dev world, or bump the tile format, to see it.
- Ground (ADR-101, tile format 14): the top and filler block per cell come from the generator's own surface rules (`NoiseBasedChunkGenerator.buildSurface`, the overload without a world region), run on one column per 4-block cell of each stand-in chunk (`PreviewFeatures.ruled`), not from a biome guess. Pitfalls: `ChunkAccess.getHeight` already returns the top block (a first run read the block under it everywhere); the noise chunk is built once per tile with an empty `Beardifier`, since the real one asks the real world for structure references and generates chunks from a preview thread; a throw in the rules falls back to the guess, logged once. Judge the ground with `/farfield spike surface <biome>` (see `farfield-feature-spike`) before judging it by eye. Every format bump rebuilds all preview tiles on a server: warn the user of minutes of background work after a deploy.
- Climate and biome samples are the pack's cost (ADR-102): in the pack one climate sample costs about 0.5 ms under C2ME and Terralith's splines, so a per-block or per-quart-in-3D biome read made a tile take 35 to 55 s where dev took 5. The surface rules and the stand-in read one biome sample per quart column per tile, shared with the features. Never add a per-block or 3D biome lookup to a preview path without timing it in the pack. Check the surface rules' noise chunk computes no density (`SurfaceNoise`): its preliminary surface level is the bottom of the world, so no mod density runs from a preview thread for it.
- Storage: zstd files `preview/t.<x>.<z>.ffp` in the world save (`PreviewStore`). Before a tile is written, `PreviewStore` runs its key-table hook (`beforeWrite`, as `SectionStore` does): a tile names block and biome ids that must already be on disk, or a restart reassigns them and the tile shows the wrong blocks (ADR-080). Any new store that writes key ids takes the same hook. When the format changes, delete the old folder at open (the ADR-038 `L8` folder was removed that way). Never read old-format tiles.
- Cost, from the saved game logs: about 0.2 to 1.1 s per tile on 4 threads (`Noise preview threads: 4`, 2026-10-24 logs: the 4096-block radius in about 2 min), about 2.6 s per tile on the 2026-10-18 logs (about 5 min). Tiles are chosen nearest first, then in front of the view (`NoisePreview.schedule`), on the `preview_threads` pool; the planner wakes every 0.5 s so idle threads get work quickly. Before proposing a new stat or log line, grep the code and the saved logs: `Noise preview of ...: N tiles built in the last minute` already prints every minute. Thread count: `preview_threads` (Auto by default). Judge a change from the log timings, then relaunch: the second open must build nothing and still print `every tile ... is built`.
- Real chunks (ADR-039): a preview column beside a loaded real chunk goes down to that chunk's real ground (`PreviewVoxels`), so a preview shore beside real sea drops to the sea floor. Real columns carry two mask materials: opaque up to the real ground, translucent (`farfield:preview_mask_fluid`) up to the real fluid's top. Preview water thus shows no wall toward real water, while preview land shows its cliff. Real ground and fluid top are read per chunk from the real level-4 voxels (`PreviewLayer`). See `farfield-lod-renderer` for the renderer side.
- Verify in the Fabric dev client at a spot never generated (for example 6000, 0): from above, then low at y 120 toward real terrain. Procedure in `farfield-dev-client-check`. NeoForge and Sodium are not verified yet.
- Snow on tree tops (ADR-049): a kind carries a snow layer when its crown top is cold enough. Spruces are `TIERED`, pines narrow cones, both without row corners, as vanilla's placers. Detect vanilla placers with `instanceof`, never by class name (intermediary on Fabric outside dev). To compare a preview tree with a real one, find real terrain beside the preview and toggle `/farfield preview off`: what vanishes is preview. When a shape looks wrong, dump the stored tile's kinds from a temporary core test (`PreviewStore` on `<save>/farfield/preview`) before changing code.
- Icebergs (ADR-054): frozen ocean spires come from vanilla's surface rule (`SurfaceSystem.frozenOceanExtension`, three noises from the world's `RandomState`), not from features: the preview raises sea samples to the same top. Read vanilla's surface rules before inventing a shape for any other terrain the preview lacks.
- Inspecting a stored tile or a block's class: write a temporary test under `core/src/test/java/io/lakio/farfield/core/probe/` that prints `PROBE` lines, run `./gradlew.bat :core:test --tests '*TileProbeTest' --no-daemon -i --rerun-tasks` (without `--rerun-tasks` Gradle reuses the cached result and prints nothing), grep `PROBE`, then delete the folder before committing.
- Plants and villages (ADR-041): `PreviewTrees` also follows huge mushrooms, bamboo, block columns (cactus), single blocks and random patches. Blocks without a collision shape that the LODs draw as plants (grass, flowers, ferns; ADR-059, ADR-060) are kept: each chunk stores its plant kinds and their count per chunk (`PreviewTile.setPlants`, `plantEntry`), read from the biome's vegetal features. Level 0 places a plant in the block above the ground where the block's hash falls under the chunk's cover; coarse levels use the covered ground (see `farfield-lod-renderer`). Plant patches try with `PLANT_PATCH_SUCCESS` (0.2, tile format 10): measured, not guessed. To check a density, count the plants on the ground of generated chunks (the block above the `MOTION_BLOCKING_NO_LEAVES` top, so plants under a forest canopy count; `ChunkAccess.getHeight` already returns the top block, `Level.getHeight` the block above it) and compare the share of columns with `1 - exp(-n / 256)` of the preview's `grows ... N plants` line. Find a test biome at its surface: `getBaseHeight(..., OCEAN_FLOOR_WG)` above sea level, then the noise biome at that height, with the same biome 64 blocks around; `findClosestBiome3d` at a fixed y returned a savanna under a mangrove swamp and a plains over the sea. 0.8 drew about four times the real plants in plains, meadows, savannas and forests. Plants are built only in full sections, not in the single layers built for neighbor faces (`layerAxis >= 0`), where a plant would hide a neighbor's face. Each kind needs its ground (grass or snow, mycelium, sand).
- Villages: `PreviewVillages` takes the village structure sets, asks each placement for its candidate chunk per region, and keeps it when a village of the set accepts the biome. Houses are approximate boxes, not the game's pieces. Placement on land: try the candidate center first, then retry around it many times. A center in a lake left 2 houses on an islet until the tries were raised to spread along the shore. Judge a village by its houses, not by its center.
- Density reads are cached per column (ADR-057): the surface search reads `finalDensity` through a `SinglePointContext`, which ignores vanilla's cache markers, so each read recomputed the 2D terrain functions (continentalness, erosion, ridges, their shift noises, the splines). `ColumnDensity` honors `flat_cache` and `cache_2d` (last column) and `cache_once` (last point), as `NoiseChunk` does. Any new density read in the preview must go through `ColumnDensity`. Measured on a frozen sea: a tile 569 to 259 ms, the 558 tile files byte-identical. The minute line prints the stage times (`heights`, `cells`, `biomes`, `villages`, `trees`, `write`). Left after the caches: biome lookups (31 % of samples, mostly the frozen-sea check per cell) and the 3D noise (25 %).
- Coverage across a pack: the server logs hold one `Noise preview: <biome> grows N trees per chunk of K kinds, M plants of J kinds` line per biome. Survey them on the pack server (`data/logs`, rotated `*.log.gz` plus `latest.log`) with `zgrep -h "Noise preview: .* grows"`, then count per namespace the biomes under 1 tree per chunk. Last survey (2026-10-28, 190 biomes): 52 of 60 Biomes O' Plenty biomes and 34 of 53 vanilla biomes were under 1 tree per chunk, so the gap is mod trees the preview does not recognise.
- Known and not caused by the preview: a darker vanilla water rectangle at the render distance also shows with the preview off. Log it as a separate defect.
- Preview drawn over real water or sand (double water blend, preview grass on real sand): the mask is missing the real top-level sections near the player. Fix the streaming side first (`farfield-lod-streaming`, background fetch of the real terrain). Water above the sea reads sky light 15: that is not a lighting bug. The exception is a preview face on a tile border: it took the mesher's full-sky fallback where the neighbor tile's light belongs, which is the suspected cause of white bands on the preview's sea floor. Cause found (2026-10-25), replacing the earlier tile-border candidate: a ground voxel under the sea that is filled only partly shows a neighbor's side above its fill, and `PreviewVoxels` gave that face full sky light 15 instead of the water's. The fix lights those voxels with the water's light (the `water >= 0 && blocks < s` branch of the sky-light write in `PreviewVoxels`). Regression test: `PreviewTest.partlyFilledGroundUnderTheSeaTakesTheWatersLight`; it fails without the fix (`expected: <7> but was: <15>`). Unit proof only: confirm with an A/B capture at the same spot, fix on and off, before calling the bands gone. A preview regression test proves its fix only if it fails without it: `git stash push` the one main file, run `./gradlew.bat :core:test --tests "*PreviewTest"`, expect the failure, then `git stash pop`. Procedure in `farfield-dev-client-check`.
- Sea floor under preview water: on `farfield-test`, `/locate biome minecraft:warm_ocean` gave 208, 75, 2784. Teleport to y 95 with pitch 22 to look at the preview sea from above the water. Add that spot as a row in `docs/test-worlds.md`.
- Underwater features (corals, sea-floor trees) were missing from the preview (user pass, 2026-10-27): the tiles held them, but `PreviewVoxels`' `Stamp` wrote feature voxels only into air, and a preview column fills its sea before the features are stamped. Fixed by ADR-108: a feature voxel also takes the place of the preview's water (`Stamp.water`, set from `tile.water()` in `features`). When a feature shows in the real LODs and not in the preview, confirm the tile holds it first, then read the stamp. Kelp and seagrass in the preview's water: ADR-105.
- Java pitfall in feature code (ADR-079): fastutil's `IntArrayList.add` returns `boolean`, so chained calls do not compile. Write `list.add(a); list.add(b);`. The compile error seen: `PreviewFeatures.java:326: error: boolean cannot be dereferenced .add((int) key).add(best);`. Compile the loaders (`:neoforge:compileJava :fabric:compileJava`) after each such edit.
- Preview load starves chunk generation (measured 2026-10-28 on the 16-core pack server, `Noise preview threads: 5`): one minute of the preview used 255 s of CPU (about 4.3 cores) against 35 s for the chunk worker, and a tile took about 6.8 s with features. Real terrain then arrived only as fast as worldgen got cores. Linux ignores Java thread priorities, so a lower priority did not yield. Read the load with the `LOD CPU usage over 60 s` line and the minute line `Noise preview of <dim>: N tiles built in the last minute`. Open fix, not built: the preview yields to one thread while a player's new chunks are generated or ingested, or `preview_threads` Auto (one per three cores) is capped. Ask the user before building it.
