# Farfield LOD renderer

The renderer needs an OpenGL 4.6 context on both loaders, and only Fabric can fall short: vanilla 1.21.1 asks GLFW for a 3.2 context. Keep the context request in `WindowMixin` (`common/src/main/java/io/lakio/farfield/mixin/client/WindowMixin.java`) as an `@Inject` before `glfwCreateWindow`, never a `@Redirect`: Sodium redirects the same call, Mixin then skips one of the two depending on load order, and the game silently runs on 3.2 with LODs disabled (log: `@Redirect conflict`, then `OpenGL 4.6 is not available`). The inject probes 4.6 with a hidden window and puts vanilla's 3.2 hints back if it fails; it stays `require = 0` because NeoForge creates its window earlier at 4.6 with no such call. On Fabric, check for `OpenGL 4.6 context available` in the log.

- Frame cost: the render path allocates nothing per frame, caches the section selection, sends only the face directions that can face the camera (quads stored per pass and direction, `FaceDirections`; the stat line says `N of M quads sent`), culls back faces, draws opaque faces after a depth pre-pass (ADR-043), and times the GPU per pass. Judge cost from the `LOD renderer` stat line (render-thread and GPU microseconds per frame), not from F3 alone: F3 fps moves with the scene.
- A/B: `/farfield render off` at the same camera spot gives the no-LOD baseline.
- Depth pre-pass (ADR-043): `lod.frag` is built three times (`DEPTH_ONLY`, `EARLY_Z`, plain) by `GlProgram` defines; a new uniform goes into `LodRenderer.Shader` and `use()`, which set it on every variant. A new `discard` in the opaque path must go into the `DEPTH_ONLY` branch too, since the shaded opaque pass draws with `GL_EQUAL` and no discard. Keep `invariant gl_Position` in `lod.vert`. `/farfield debug prepass off` compares GPU times in one run (not saved).
- Pre-pass lists (ADR-044): a section goes to the discarding pre-pass only when it overlaps the compiled-sections grid or has an opaque face with holes (`MaterialColors.CUTOUT`); the others use `SOLID`, a depth shader without any `discard`. Keep `SOLID` free of discards: one discard anywhere in a shader cost about 320 us there. A new reason to discard in the opaque path must also send its sections to the `DISCARD` list.
- GPU timing: measure with the frame rate uncapped (`maxFps:260`, vanilla's "Unlimited", and `enableVsync:false` in the run dir's `options.txt`; the `dev/client` template has both). At the default 120 fps cap the laptop GPU lowered its clocks and absolute times moved between runs (the same no-pre-pass case read 3,421 then 3,630 us). Compare variants within one run (a debug switch), reading the second stat line after each switch; the first mixes both.
- Zoomed view (spyglass, any FOV narrowing): the narrow projection must not raise the detail of sections outside the view. `LodRenderer.updateDetail` keeps the options' FOV detail as `outsideDetail`, and `LodSelector.setOutsideView(inView, outsideDetail)` splits sections outside the view at that detail at most (ADR-063, pinned by `LodSelectorTest.sectionsOutsideTheViewKeepTheUsualDetail`). Without it, 62.6 section sizes split every section around to level 0 and filled the quad budget.
- Quad room before residence: a mesh allocates its quads first. When the budget is full, evict only sections the last selection did not use and retry. Still no room: keep the previous mesh (it turns stale) or wait. Never keep an empty resident marked ready, since the selector then never requests it again.
- Flicker: never evict a mesh the selector still falls back to. Evicting a non-drawn parent makes LODs snap to the coarse level every few seconds. Prove a fix with the stat line: meshes uploaded and freed stay near 0 in steady state.
- Request order: `LodSelector.select` walks the grid in x/z order and calls `want` on each missing section as it goes, and the renderer builds the requests it receives first. So the sections the walk meets first are built first, often far away and out of view, while the ones next to the player wait. The renderer now requests sections nearest first, then in view direction first, and reruns the selection when the view turns about 25 degrees. A change must keep the total work and only reorder it. The meshes-in-flight cap (`MAX_IN_FLIGHT`, 64) is a queue size: try values with a temporary `-Dfarfield.meshInFlight` switch, read the result on the `LOD renderer ready` line, then remove the switch.
- Optional mixins stay `require = 0`, so a mod that conflicts with one does not crash the game or a dedicated server.
- Keep the success-branch log line (renderer name and GL version). A path that logs nothing on success cannot be verified.

Verify in game with the `sections drawn` stat line and the procedure in `farfield-dev-client-check`.

- Shader edits have no offline check here: GLSL compiles only when the client links the program. No validator exists on this machine (`glslangValidator`, `glslc`, a VulkanSDK folder and the Gradle cache for shaderc/glslang were all absent), so `gradlew build` passing proves nothing about the shaders. Say so in the report, and ask before the launch that compiles them.
- Shared GLSL: `GlProgram.read` expands a line that is exactly `#include "name"` (trimmed) into the file `shaders/name` before compiling. Put a declaration used by both `lod.vert` and `lod.frag` in such an include (e.g. `biome_tint.glsl`), and keep each include line alone on its line.
- Per-plant tint: a plant is one block wide, so `lod.vert` blends its tint once per vertex (`v_plantTint`) and `lod.frag` uses it for plants; other faces still blend per fragment.

## Matching vanilla at the edge

Compare a shade or a seam with numbers, not by eye: sample the same surface on both sides of the edge from a full-resolution capture, and split vanilla from LOD pixels with `/farfield debug levels` (tinted pixels are LOD).

To localize a new seam inside LODs, capture the same camera spot before and after the change, diff the two grayscale images (`abs(a - b)`, amplified about 6x), and check where the difference lands. A difference that falls on the 32-block section grid points at the shader or the per-section data, not at the terrain.

- Hand-off: `lod.frag` discards a fragment only on a chunk section the game really draws: compiled (a bit grid of `LevelRenderer.isSectionCompiled`, rebuilt every 8 frames; Sodium overrides the method) and within the terrain renderer's own distance rule (Sodium: the section grown by one block, render distance on both axes; vanilla: `ChunkTrackingView.isInViewDistance`, and no more than the render distance in sections above or below the camera's section, as `SectionOcclusionGraph.getRelativeFrom`: vanilla compiles those sections but never draws them, and a camera high above the sea showed black holes at the vanilla edge). A circle overlaps whole sections (translucent ice blended twice); a rule without the compiled grid leaves holes on chunks still building. A section enters Sodium's render lists one frame after it is compiled: LODs give way only once it has stayed compiled for two passes, else a band shows nothing for one frame. The outer 3 chunks of the grid are read every frame.
- One-frame flicker: ask for a video, extract frames with ffmpeg (named by time), and let the user point the frame. Reproduce by flying with the forward key held (AZERTY: Z, scan code 0x11) and 40 PrintWindow captures; detect one-frame holes as dark gray 16-px blocks present in one capture and absent in both neighbors. Validate the detector on the failing run before trusting a 0.
- Light: quads carry sky and block light; `lod.frag` samples vanilla's lightmap filtered at `level / 16`, like `minecraft_sample_lightmap`, bound from `lightTexture().turnOnLightLayer()` then `RenderSystem.getShaderTexture(2)` on unit 11 (the atlas uses 10). An exact `texelFetch` reads about 5 % brighter. Never re-derive the lightmap formula.
- Ambient occlusion: every level stores its opaque voxels (1024 ints, 4 KB per section) in a storage buffer by slot (section info.z = 1). Each slot also holds a neighbor table (27 ints: its 26 resident same-level neighbors, own slot + 1 or 0), written on upload by `linkNeighbors` and cleared on eviction in `LodRenderer`. `lod.frag` applies vanilla's smooth-light formula per fragment and reads the voxels across section borders. Never treat a neighbor outside the section as open: that draws a straight lighter line on every section border. Never stop occlusion at one level: that draws a curved ring. Opaque pass only.
- `FogRendererMixin` moves vanilla's normal terrain fog out to the LOD fog; it leaves alone any fog whose end is not the far plane.
- Dimension fog (`extend_dimension_fog` in `farfield-client.properties`, labelled Vanilla / Pushed Back on the settings screen): Vanilla (`false`) keeps the dimension's own fog, so in the Nether the LODs fade into it and look like no LODs. Pushed Back (`true`) moves the LOD fog out to the far plane, opaque at `MAX_DISTANCE` (4096 blocks). Pushed Back does not remove fog: cutting the LODs off at 4096 without it leaves a hard edge.

## Geometry and data

- Quad layout: material 16 bits, biome 9, sky and block light 4 + 4, fill 3 (8 bytes). Check new fields against the largest worlds' key tables (6,460 states, 127 biomes in a 398-mod pack).
- Heights: on level 0, `MaterialClassifier.PARTIAL` blocks (snow layers, bottom slabs, carpets) keep their height from the color table; on coarser levels every voxel carries a fill (ADR-028) and `lod.vert` lowers top edges to it. Fluid tops sit at vanilla's still-water height, 8/9 of a block, on every level: level 0 takes it from the color table (`MaterialColors.height`), coarse levels lower the top by the same ninth in blocks after the fill. A fluid at a full block next to vanilla water leaves a dark 1-px line on the chunk edge. Changing the mip rules means bumping `MIPS_VERSION` in `LodWorld`, so worlds rebuild their coarse levels once at open (logged when queued and when done).
- Level of detail is screen-space (ADR-023): `detail = focal px / (32 * voxelPixels)`, default 6 px (ADR-027), `/farfield detail N`. Apply a new detail only once two consecutive frames agree within 2 %: the first frame's projection can be infinite or wrong.
- Colors: `MaterialColors` (baked face tiles and their mean colors, untinted + tinted parts, block heights) and `BiomeTints`. Resource reload and level change rebuild both tables.
- Biome blending (grass, foliage, water tints): the vertex shader passes the untinted part, the tinted part and the quad's biome; `lod.frag` picks the tint per fragment as a mean over a (2r+1)-block square, r = `u_biomeBlend` (vanilla's Biome Blend option, read from `mc.options`). Surface biome per 4x4 column is per section in `biomeColumns` (binding 7, written by `SurfaceBiomes`); neighbors come from the neighbor table, as for occlusion. Radius 0 must render exactly as before the feature.
- Draws are indexed (ADR-048): commands are 5 ints (count, instances, first index 0, base vertex = group start x 4, base instance = slot), one shared index buffer of 131,072 quads, `lod.vert` takes the quad from `gl_VertexID / 4`. Stride and offsets use `COMMAND_BYTES`; anything that builds or reads commands must follow it.
- Neighbor rewrites: a face on a section border takes its light from the neighbor, or full light while that neighbor is missing (white sea floors with straight edges). The mesher reports those borders (`BinaryGreedyMesher.borderFaces`, kept on the resident) and `applyRewrites` meshes a resident again when the neighbor it reads is written, besides the sections with translucent faces. The extra work was within noise on a streamed fill (5,765 against 5,881 mesh jobs).
- Coarse water and light (ADR-071): a coarse voxel keeps its brightest block's light, in water the top block's. Faces in front of coarse water take less by its depth (`BinaryGreedyMesher.waterSky`, `setVoxelBlocks`, `borderLight` with a classifier); without it sea floors on levels 3 and 4 took full light (white squares along ridges, gone when zooming). Specks of one pixel under the sea: measure first with the textures off (`/farfieldclient textures 0`) and an isolated-bright-pixel count in a fixed box; lit faces and cracks look alike.
- Mesher reads go through `SectionCache`; the store's write listener invalidates it. A new path that reads stored sections for meshing must use `readSection`, or a rewritten section can be meshed from stale data.
- Sections the game draws entirely are skipped on the CPU (`gameDrawsAll`, ADR-047): it mirrors `vanillaDraws` of `lod.frag` over the same compiled-sections grid. A change to the hand-off rule in the shader must go into `gameDrawsAll` too, or a section is skipped where the shader would keep fragments (a hole at the vanilla edge). GPU occlusion culling was tried and dropped (branch `experiment/occlusion-culling`): the LODs draw before the game's terrain, so the near terrain that hides the horizon is not in their depth.
- Unknown is not air: a stored section holds 4 chunks or more, and a chunk without data reads as air. Real sections mesh with `setEmptyColumnsUnknown(true)` and `addEmptyColumns` on the neighbor planes, and a missing horizontal neighbor counts as solid, for translucent faces only: water draws no wall toward chunks without data, ground keeps its wall. The edge wall of real ground seen through the preview's water (real floor above the preview's) is a known open case.
- Mask material: a preview section over real chunks is filled with an opaque material (`PreviewLayer.MASK_KEY`, unknown to the game, never drawn). `LodRenderer` drops its quads, both when counting and when splitting opaque from translucent, so the preview's faces toward real terrain are hidden with no wall of water or ground at the border. Keep the mask out of the block-state warning path (`MaterialColors` skips it).
- Translucent pass: each section stores opaque quads first; the translucent draw offsets `gl_VertexID` with the command's `first`. Translucent faces cull against neighbor solid layers. A translucent voxel hides only translucent neighbors of its own kind, fluid or not (`MaterialClassifier.isFluid`): water against water and ice against ice stay culled, ice against water shows both faces, because vanilla draws two layers over a frozen sea (ice top, water top 8/9 below). With two translucent layers, translucent sections draw far to near by center distance; in selection order a neighbor's water blends over nearer ice as dark lines along section borders (ADR-055). Waterlogged blocks (kelp, seagrass, waterlogged slabs) are that water for the mesher too: `BlockKeys` returns `MaterialTable.packFluid()` for them, not a translucent non-fluid (plants standing in water, kelp and seagrass, pack as `packSubmerged()` instead, ADR-065). Test the waterlogged state before the full-block rule: a kelp body has a full outline and was classed as a cube until ADR-064. Otherwise every face between them and the surrounding water shows as dark squares around kelp (ADR-063).
- Every visual distance is a user choice, shipped with its command (`/farfield textures`, `/farfield detail`) and an entry in the E.8 settings screen. Defaults are the best quality the measured cost allows (the user's call: no measurable cost, so the best value stays the default, and the trade-off is left to the settings screen later). Measure the cost at that default and record it in the ADR.

- Vanilla-mirroring settings: when the user asks a LOD effect to follow a vanilla option (Biome Blend, render distance, fog), read the live vanilla option value and copy its semantics exactly. When the vanilla option is off, do nothing extra, so the output matches the pre-feature build.
- Partial blocks (snow layers, slabs) are full cubes on coarse levels: their face tiles must carry no cutout, or the cube shows holes while hiding its neighbors (ADR-050; `MaterialColors` fills them with the face color). "Transparent leaves" far away: check the level colors, then the cutout of the voxel's material.
- Preview keys carry a level offset (`PreviewLayer.KEY_LEVEL_OFFSET`): read a level from a key that may be a preview one with `drawLevel(key)`, never `LodKey.level(key)` (ADR-051: level-0 preview sections meshed as coarse ones).
- Holes in LODs: first scan the section data and its mesh offline (a temporary core test on `<save>/farfield/preview` or the store); complete data and mesh point at the renderer.

- Plants (grass, flowers; ADR-059): class `MaterialClassifier.PLANT`. The mesher emits two diagonal quads per plant, kept in their own group (`PLANT_GROUP`, after the translucent groups) and drawn in the cutout pass whatever the camera's side, since the shader turns them toward the camera. `MaterialColors.buildPlant` puts the model's first quad sprite on face 0 (height along U, width along V, biome tint kept) and copies it to the other faces. On coarse levels plants count as air, so they add no fill or occlusion, but the ground under them is not left bare: `MipBuilder` gives a voxel whose top is ground under plants a covered material (`MipBuilder.Shapes.covered`: ground, plant, and the quarters of the cover), its top face speckled with that plant's sprite. A change to that rule bumps `MIPS_VERSION`, so worlds rebuild their coarse levels at open. In `lod.frag`, plants take no normal and no ambient occlusion, their holes are always cut, and they vanish beyond the texture distance instead of becoming solid rectangles.
- Plant-only shader code goes in the `PLANTS` program variant (`lod.vert`/`lod.frag` under `#ifdef PLANTS`, drawn only for the plants' list), never in the shared shaders: plant tint per vertex in the shared vertex shader cost the opaque pass 126 us while saving the plants 35 us. Shared GLSL lives in an `#include "name"` file (`biome_tint.glsl`) that `GlProgram` inlines.
- Kelp and seagrass (ADR-065): a translucent fluid with `MaterialClassifier.hasPlant`. Keep every water rule on them (culling, neighbor planes, mips, preview masks) and add only the plant: faces take `fluidOf` (the water's material), the finest level adds the diagonals with the plant's own material. A coarse classifier must pass `fluidOf` through, or kelp voxels stored in coarse levels draw their faces with the kelp's look. The plants' pass draws before the translucent one, so the water blends over the kelp.

Known open gaps (E.7 in the milestone plan):
- Fences, walls and panes are invisible in LODs; stairs are full cubes.
